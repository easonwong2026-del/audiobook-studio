# Audiobook Studio v3.2.0 UI/UX 重构 PRD

> 文档状态：历史 PRD（v3.2 UI/UX 重构）；当前 UI 行为以代码、README 和最新 release 文档为准。

## 目标

将 Audiobook Studio 从“功能集合型工具”升级为“有声书生产工作台”。

本版本不增加 TTS 核心能力，重点优化用户完成一本书的操作流程、信息层级和页面布局。

## 核心原则

1. 按用户工作流组织页面，而不是按内部模块组织。
2. 角色、声音、试听形成完整闭环。
3. 合成过程展示生产状态，而不是技术日志。
4. 高级参数默认隐藏，避免主流程复杂化。

## 新工作流

```
工作台
  ↓
项目制作
  ↓
角色与声音
  ↓
合成中心
  ↓
试听质检
  ↓
发布导出
```

## P0 改造

### 1. 工作台 Dashboard

展示：

- 当前项目
- 完成章节数
- 合成进度
- 待处理问题
- 快捷继续操作

### 2. 角色与声音中心

替代单独音色管理方式。

目标模型：

```
角色
 ├── 人物信息
 ├── 当前声音
 ├── 试听
 ├── 更换声音
 └── 使用状态
```

角色列表显示：

- 角色名称
- 描述
- 已绑定声音
- 绑定状态

### 3. 合成前检查

启动整本合成前检查：

- 剧本有效
- 所有角色存在
- 所有角色已绑定声音
- 数据目录可写
- 模型环境可用

## P1 改造

### 合成中心

从日志驱动改为任务状态驱动。

展示：

- 当前章节
- 当前段落
- 完成比例
- 队列
- 暂停/恢复
- 失败重试

### 音色卡片

支持：

- 试听
- 替换
- 收藏
- 分类

## P2 改造

未来支持：

- 根据角色描述推荐声音
- 多版本角色声音方案
- 项目模板

## 技术约束

保持以下模块稳定：

- services
- repositories
- lib
- tts_engine
- audio_pipeline

主要调整范围：

- ui/
- app.py UI 接线
- theme/css

## 验收标准

用户第一次打开软件，可以回答三个问题：

1. 我现在在哪一步？
2. 下一步应该做什么？
3. 当前哪里需要处理？

如果无法回答，说明信息架构仍需优化。
