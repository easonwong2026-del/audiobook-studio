# Audiobook Studio Pencil UI 分阶段导入计划

> 文档状态：历史 UI 重构计划（不作为当前执行计划；当前实现以代码、README 和最新 release 文档为准）
> 计划基线：`fix/v3.2.1-product-polish` / `f5eecca`  
> Pencil 设计源：`pencil-new.pen`  
> 原则：先规划、分批实施、逐页验收、随时可回退  
> 本文档本身不包含任何 UI 或业务代码变更。

## 1. 任务目标

将 Pencil 中已经完成的 Audiobook Studio 界面设计，分阶段还原到当前 Gradio 项目中，同时保证现有业务流程、数据结构和回调逻辑不被破坏。

本次重点是：

- 尽量还原 Pencil 的视觉层级、布局、配色、间距和组件状态。
- 修复字体与背景对比度不足、大块黑色压迫、布局留白失衡等体验问题。
- 保持桌面音频制作工作站的专业感，不改成消费类 App 风格。
- 所有页面采用一致的设计语言，但不通过高风险全局 CSS 强行重排 Gradio。
- 每一批修改均可单独测试、审阅、提交和回退。

## 2. 明确不做的内容

本轮只做 UI 还原与必要的展示层整理，不新增大型功能，不改变核心业务逻辑。

以下内容原则上不修改：

- `structured_script.json` 数据结构
- `voice_bindings.json` 数据结构
- 项目创建、打开和保存协议
- 音频生成流程
- IndexTTS2 调用方式
- 导出文件结构
- 现有业务回调的输入输出语义
- 角色、声音和项目的持久化规则

如果设计实现确实需要调整回调连接，只允许增加轻量的 UI 适配层，不在回调中重写业务规则。

## 4. 上次失败的原因与本次强制约束

上次导入后出现“只有左侧边栏、右侧内容消失”的问题，主要风险来自全局样式覆盖和固定几何尺寸。

本次禁止以下做法：

- 不对 Gradio 根节点或主容器设置 `width: 100vw`。
- 不在全局设置 `overflow-x: hidden` 来掩盖布局问题。
- 不依赖 Gradio 动态生成的 `#component-*` ID。
- 不对 Gradio 关键包装层使用 `display: contents`。
- 不用全局 `display: none` 隐藏未知结构。
- 不对页面主容器设置可能裁切内容的固定高度。
- 不用大量绝对定位拼出整页。
- 不用大量 `!important` 强行覆盖组件默认布局。
- 不把设计稿的固定像素画板直接等比例复制为网页固定宽高。
- 不在一个提交中同时重写全部页面和全局主题。

必须遵守以下实现方式：

- 使用稳定的 `elem_id` 和 `elem_classes` 作为样式挂载点。
- CSS 以页面或组件作用域开头，避免影响其他页面。
- 保留 Gradio 原有的弹性布局和可见性机制。
- 固定尺寸只用于图标、头像和少量明确的控件，不用于整页骨架。
- 页面布局以 `minmax()`、`max-width`、`gap` 和弹性比例为主。
- 每次只改一个共享层或一个页面，并立即做截图回归。
- 任何公共样式改动都必须检查七个页面。

## 5. 总体批次安排

建议拆成五次完成，每次结束后由用户查看实际页面，再决定是否进入下一批。

| 批次 | 内容 | 建议完成范围 | 验收关口 |
|---|---|---|---|
| 第一次 | 设计盘点与安全骨架 | 阶段 0–2 | 七页均能打开，右侧内容完整 |
| 第二次 | 核心入口页面 | 阶段 3–4 | 工作台、项目页还原通过 |
| 第三次 | 角色与声音专项 | 阶段 5 | 大量角色场景及绑定流程通过 |
| 第四次 | 生产与质检页面 | 阶段 6–8 | 合成、试听、补录流程通过 |
| 第五次 | 导出、响应式和最终回归 | 阶段 9–11 | 全流程、视觉和性能验收通过 |

每一批都形成独立提交，不把未验收的下一批内容混入当前提交。

## 7. 每次实施的固定工作流程

每一批都遵循以下步骤：

1. 确认当前分支和工作区干净。
2. 读取本批对应的 Pencil 画板。
3. 截取实施前页面。
4. 只修改本批范围内的文件。
5. 启动应用并检查浏览器控制台。
6. 在三种窗口尺寸下截图。
7. 执行本批功能回归。
8. 执行相关自动化测试。
9. 对比 Pencil、旧页面和新页面。
10. 用户确认后才提交本批。
11. 本批提交后再进入下一批。

如果任一阶段出现以下情况，立即停止扩展范围并回退本阶段：

- 右侧内容不可见
- 页面主区被挤出视口
- 导航无法切换
- 业务回调失效
- 数据结构发生非计划变化
- 其他页面因共享 CSS 出现明显回归

## 8. Git 与回退策略

- 不直接在稳定基线上连续堆叠全部改动。
