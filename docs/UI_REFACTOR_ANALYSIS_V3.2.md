# Audiobook Studio v3.2.0 UI/UX 重构审计

> 文档状态：历史审计记录（v3.2）；不作为当前 UI 实施计划，当前实现以代码和 README 为准。
> 基线：v3.1.1  
> 审计范围：`app.py`、`ui/navigation.py`、`ui/pages/*`、`ui/shared.py`、`ui/theme.py`  
> 结论：本次为纯 UI/UX 产品化重构；不修改 `lib/`、`services/`、`repositories/`、推理逻辑或数据协议。

## 1. 当前页面结构

v3.1.1 使用左侧七项平铺导航，页面与现有能力的映射如下：

| 入口 | 页面模块 | 当前职责 |
|---|---|---|
| 概览 | `overview_page.py` | 项目书架、项目状态与三个快捷按钮 |
| 项目 | `project_page.py` | 新建/打开项目、章节树、数据目录 |
| 音色资产 | `voice_page.py` | 音色库、录制/保存、角色音色绑定、试音 |
| 合成 | `synthesis_page.py` | 合成范围、参数、队列、暂停/恢复、运行日志 |
| 试听与质检 | `review_page.py` | 章节试听、段落试听、局部重合成 |
| 导出 | `export_page.py` | 整书/字幕导出 |
| 角色补录 | `supplement_page.py` | 角色单独补合成、试听与导出 |

`app.py` 负责组装页面、维护 `SessionState`、复用打开项目刷新链，并把 UI 事件交给现有 Service。页面 Builder 与事件编排已经分离，能够在不回迁业务逻辑的前提下调整信息架构。

## 2. 用户完成一本书的当前路径

1. 在“项目”上传 `structured_script.json` 并创建、打开项目。
2. 前往“音色资产”，在音色库、录制、上传、试听、角色绑定等区域间切换，为每个角色绑定声音。
3. 前往“合成”，选择章节和参数后启动任务；通过日志和队列确认运行状态。
4. 前往“试听与质检”，按章节或段落试听；必要时重合成。
5. 若需要额外台词，再单独前往“角色补录”。
6. 前往“导出”，生成有声书及字幕。

该路径实际是线性的生产流程，但导航以独立功能模块呈现，用户必须自行判断下一步应前往何处。

## 3. 当前页面问题

- **导航没有工作流语义**：七个同层入口平铺，项目、角色、合成、质检、导出的先后关系不可见。
- **首页缺少项目态**：概览只有书架和快捷按钮，不能在打开项目后清晰回答“现在做到哪里、下一步是什么、哪些事项阻塞交付”。
- **角色与声音任务被资产视角掩盖**：绑定角色是合成前的关键关卡，却混在“保存克隆声音”“音色浏览”等资产管理操作中。
- **合成操作被日志主导**：日志占据主要视觉面积；队列、进度、可恢复状态和操作按钮缺少生产控制台层级。
- **质检与补录割裂**：用户发现问题后要在“试听与质检”与“角色补录”之间自行判断，不符合“发现问题—修复—复听”的闭环。
- **高级参数过早暴露**：beam、情感覆盖、强度和语速与主操作同级，给常规“一键按剧本合成”增加决策负担。
- **项目设置干扰主任务**：数据目录和删除操作与项目导入/打开并列，容易分散注意且风险较高。

## 4. v3.2 新信息架构

产品定位从“功能集合”调整为“有声书生产工作台”。导航遵循一次生产的阶段，低频设置收纳到页面内。

| 导航阶段 | 页面 | 核心问题 | 收纳的既有能力 |
|---|---|---|---|
| 🏠 工作台 | `overview_page.py` | 项目现在处于什么状态、下一步是什么？ | 当前书、书名、章节/段落进度、角色绑定状态、最近项目、待处理问题、快捷行动 |
| ① 项目 | `project_page.py` | 导入或切换哪一本书？ | 创建/打开项目、章节树；数据目录移入“工作区设置”折叠区 |
| ② 角色与声音 | `voice_page.py` | 谁还没有声音、要给谁配什么声音？ | 角色绑定作为首要任务；音色库浏览、上传/录制、保存和试音降级为“管理声音资产”折叠区 |
| ③ 生产与质检 | `synthesis_page.py` + `review_page.py` | 如何合成、追踪、试听并修复？ | 合成进度/队列为主；日志收纳；高级合成参数收纳；章节与段落质检、局部重合成及角色补录作为同一生产阶段的工具 |
| ④ 交付 | `export_page.py` | 如何交付可发布成品？ | 有声书导出、字幕生成；显示交付前检查状态 |

为保留现有功能和最小化事件迁移，v3.2 的“生产与质检”仍由两个内部工作页面构成，但导航将它们连续呈现，不再把运行日志作为产品主视图。“角色补录”保留为生产与质检阶段的次级工具，而非顶级入口。

### 工作台的状态规则

- 未打开项目：引导“创建或打开项目”。
- 已打开、存在未绑定角色：主行动为“配置角色声音”，待处理事项显示未绑定角色数。
- 角色齐全、未完成合成：主行动为“开始生产”。
- 存在失败或未完成段落：主行动为“查看生产与质检”。
- 全部完成：主行动为“交付成品”。

该规则只读取现有 `ProjectSnapshot` / `SessionState`，不改变持久化模型或合成状态机。

## 5. 改造范围与边界

### 会修改

- `ui/navigation.py`：改为五阶段工作流导航，并为生产阶段提供二级入口。
- `ui/shared.py`、`ui/theme.py`：统一工作台顶栏、状态卡、进度条、任务卡与响应式视觉语言。
- `ui/pages/*`：重排现有组件、减少说明文本、将低频/高级操作收纳到 Accordion 或次级区域。
- `app.py`：仅调整组件装配、导航和 UI 事件接线；新增 UI 状态摘要辅助函数。
- `ui/components/`：如需复用状态卡、空状态和生产状态摘要，仅放展示/交互辅助，不放业务逻辑。
- 相关 UI 接线/页面测试与发布文档。

### 明确不修改

- `lib/`、`services/`、`repositories/`。
- IndexTTS2 推理、队列、暂停/恢复、断点续跑和音频导出实现。
- `structured_script.json`、`voice_bindings.json` 和其他数据结构协议。

## 6. 实施确认

审计确认可在现有架构内完成：所有保留能力已有独立 Handler 或 Service，重构只改变它们在界面中的编排与层级。实施将保持关键 Handler 签名与数据流不变，并以既有测试加 UI 接线测试验证。
