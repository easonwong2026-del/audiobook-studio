# V3 → V4 项目迁移说明（Migration Guide）

## 1. 什么时候需要迁移

- 新项目：**不需要迁移**，新建项目默认就是 V4。
- 旧 V3 项目：可以继续按原流程打开 / 查看 / 使用；想获得 V4 能力
  （稳定角色 ID、runtime.db、缓存复用、真实暂停继续、M4B 导出等）时，
  在「② 项目管理」选中 V3 项目，点击「复制并升级到 V4」。

## 2. 迁移行为保证

- **不覆盖原项目**：迁移是复制，V3 原目录只读，原项目保持不变。
- **创建新项目**：新项目名为 `{原项目名}-v4`（如 `雨夜书店-v4`）。
- **备份**：迁移前把 V3 项目完整复制到数据目录 `.v3-backups/{原项目名}-{时间戳}`。
- **失败回滚**：使用原子 staging 目录，任一步失败自动清理，不留下半成品。
- **重复迁移**：检测到已迁移标记（`revisions/migration-v3.json`）时复用上次结果，
  不会重复创建。

## 3. 迁移保留的内容

- 章节与片段文本（重构为 source-first 的 `source.txt` + `script.json`，lossless）
- 角色（含旁白）→ 稳定角色 ID（`speakers.json`）
- 已绑定的参考音色（复制进 `assets/voices/`，SHA 指纹去重）
- 每段的情绪 / 语速等表演覆盖（写入 `performance.json`）

## 4. 迁移后需要做的事

- 在「③ 角色与声音」检查角色（AI 识别规则已修复噪音问题），必要时人工指派 / 合并 / 锁定。
- 绑定缺失音色。
- 在「④ 生产与质检」生成计划并合成（runtime.db 从零开始，旧 V3 合成产物不迁移）。
- 在「⑤ 交付」导出 WAV / MP3 / M4B / 字幕。

## 5. 已知限制

- 旧 V3 已合成的音频文件**不迁移**（新 V4 项目重新合成；cache key 语义不同无法复用）。
- 迁移标记按源项目路径识别；若手动改动 V3 项目目录结构可能失效。
